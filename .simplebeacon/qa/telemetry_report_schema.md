# Post-Incident Telemetry Report Schema

## Purpose

Standardize the structure of exported telemetry from `cluster-keyring-sync.queryEvents()` for post-incident review, Validator sign-off, and compliance reporting.

## Event Record Schema

Each event returned by `queryEvents()` and included in the report must conform to this shape:

```json
{
  "eventId": "string (UUID)",
  "timestamp": "ISO-8601 string",
  "eventType": "string",
  "node": "string | null",
  "details": "object | null",
  "level": "info | warn | error"
}
```

### Field definitions

- `eventId`: Globally unique event identifier generated by `_recordEvent()`.
- `timestamp`: UTC ISO-8601 string. Used for 24-hour default windowing and TTL computations.
- `eventType`: One of the registered `EVENT_TYPES` (e.g. `STEK_ROTATED`, `QUANTUM_ROLLBACK`, `BACKUP_CREATED`, `AUDIT_PERSISTENCE_FAILURE`).
- `node`: Originating node identifier, or `null` for system-wide events.
- `details`: Free-form object. Examples:
  - `quantum_hybrid_rollback`: `{ reasons: [...] }`
  - `BACKUP_PRUNED`: `{ archiveId: '...' }`
  - `AUDIT_PERSISTENCE_FAILURE`: `{ error: '...', command: '...' }`
- `level`: Derived from event type:
  - `error` for `AUDIT_PERSISTENCE_FAILURE`, `quantum_hybrid_rollback`
  - `warn` for `BACKUP_IMMUTABLE`
  - `info` for all others

## Report Container Schema

```json
{
  "reportId": "string (UUID)",
  "generatedAt": "ISO-8601 string",
  "branch": "string",
  "commit": "string",
  "window": {
    "startDate": "ISO-8601 string",
    "endDate": "ISO-8601 string"
  },
  "summary": {
    "total": 0,
    "byType": {},
    "byNode": {}
  },
  "criticalEvents": [],
  "events": []
}
```

## Aggregation Rules

- `summary.total`: count of all events in the requested window.
- `summary.byType`: `{ eventType: count }` mapping.
- `summary.byNode`: `{ node: count }` mapping, with `__unknown__` for null nodes.
- `criticalEvents`: all events where `level === 'error'`, sorted newest first.

## Default Query Windows

- Unbounded queries default to the last 24 hours.
- Explicit `startDate`/`endDate` can override.
- `limit` defaults to `AUDIT_QUERY_MAX_ROWS` (1000).

## Example Generator

A small utility can be added after merge:

```javascript
const clusterSync = require('./cluster-keyring-sync.cjs');

function buildTelemetryReport(startDate, endDate) {
  const { events, total } = clusterSync.queryEvents({ startDate, endDate });
  const byType = {};
  const byNode = {};
  const critical = [];
  for (const e of events) {
    const level = levelOf(e.eventType);
    e.level = level;
    byType[e.eventType] = (byType[e.eventType] || 0) + 1;
    const node = e.node || '__unknown__';
    byNode[node] = (byNode[node] || 0) + 1;
    if (level === 'error') critical.push(e);
  }
  return {
    reportId: crypto.randomUUID(),
    generatedAt: new Date().toISOString(),
    branch: process.env.GIT_BRANCH || 'unknown',
    commit: process.env.GIT_COMMIT || 'unknown',
    window: { startDate, endDate },
    summary: { total, byType, byNode },
    criticalEvents: critical,
    events,
  };
}
```

## Storage & Retention

- Reports should be emitted to `.simplebeacon/qa/telemetry-reports/YYYYMMDD-HHMMSS.json`.
- The directory must be added to `.gitignore` to avoid leaking node names or session details.
- Retention: 90 days or per compliance policy.
