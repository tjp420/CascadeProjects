### 2.2 Canary Phase

1. Deploy `main @ bab8d644c` to **one isolated tenancy** with `MULTI_ENCLAVE_CONFIDENTIAL_MESH_STATE_RECONCILIATION_GATING_ENABLED` set to `true`.

   - `hsm_meshgate_challenge_issued_total`

1. Confirm canary telemetry is healthy for at least 10 minutes.
2. Promote the same container/hash to 100% of the fleet.
3. Disable legacy synchronous sequential fallback routing.
4. Enable `child_process.fork` based parallel transaction processing pools.
5. Monitor the master test matrix on a nightly cron.

## Section 3: Rollback & Disaster Recovery Circuit Breakers

### 3.1 L1 Trigger: Immediate code rollback

**Condition:** Anomalous CPU scheduling, timing drift, or startup failure on any node after switchover.

**Action:**

```bash
git checkout d173a2427
# or, if running from a tagged container:
# docker pull <registry>:pre-track-112
# Re-deploy and drain the canary.
```

`d173a2427` is the last pre-Track-112 baseline that contains the stable Track 1-110 gating set.

### 3.2 L2 Trigger: Emergency degradation

**Condition:** The process-isolated `child_process.fork` pool hits unexpected thread limits or file-descriptor exhaustion under production saturation.

**Action:**

1. Set `RUN_PARALLEL=false` in the deployment environment.
2. Restart the orchestrator in synchronous sequential mode.
3. File an incident ticket and attach the output of `run-all-tracks.cjs --all` plus `top`/`htop` snapshots.

### 3.3 L3 Trigger: Gating-specific kill switch

**Condition:** A specific Track 115 policy causes elevated `hsm_meshgate_challenge_issued_total` relative to `hsm_zk_mesh_state_reconciled_total`.

**Action:**

```javascript
// In hsm-vault-routes.cjs, set to false and redeploy:
const MULTI_ENCLAVE_CONFIDENTIAL_MESH_STATE_RECONCILIATION_GATING_ENABLED = false;
```

This immediately returns `503` on the `/api/vault/multi-enclave-confidential-mesh-state-reconciliation/*` routes while leaving Tracks 1-114 operational.
