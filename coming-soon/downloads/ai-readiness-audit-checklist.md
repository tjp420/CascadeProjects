# AI-Readiness Audit Checklist

## For Engineering VPs, CTOs, and Compliance Officers

**Use this checklist to self-assess your codebase before an external AI audit.**

---

## 1. AI-Generated Code Hygiene

### Pattern Fracture & Siloed Logic

- [ ] Same cross-cutting concern (auth, error handling, data fetching) implemented consistently across the codebase
- [ ] No duplicate helper functions copied from separate AI sessions
- [ ] Consistent naming conventions and file organization
- [ ] No orphaned utility files that duplicate existing library functionality

**Run:** SimpleBeacon `consolidation` + `workspace-health` + `complexity` scans

### The "Happy Path" Bias

- [ ] Every async function has error boundaries or try/catch blocks
- [ ] API endpoints return structured error responses, not silent failures
- [ ] Logging is present for all critical paths (not just success cases)
- [ ] Input validation exists on all user-facing boundaries

**Run:** SimpleBeacon `ai-residue` + `test-coverage` scans

### Abandoned Placeholders & Stubs

- [ ] Zero `// placeholder: AI implement this` or `// FIXME` markers in production code
- [ ] No empty function bodies with hardcoded `null` / `{}` / `[]` return values
- [ ] No mock data paths (`mock/`, `fixture/`, `sample/`) referenced in production builds
- [ ] All endpoints in API contracts are fully implemented

**Run:** SimpleBeacon `roadmap` + `mock-data` + `api-contract` scans

## 2. Embedded Security & Exposure Vulnerabilities

### Exposed Credentials

- [ ] No hardcoded API keys, Stripe tokens, or database connection strings in source
- [ ] `.env` files are in `.gitignore` and never committed
- [ ] No secrets in log files, localStorage, or error messages
- [ ] CI/CD pipelines use encrypted environment variables, not inline secrets

**Run:** SimpleBeacon `gate` + `token-bleed` + `sensitive-data` + `config-drift` scans

### Broken Authorization Controls

- [ ] Authentication (who you are) is separate from authorization (what you can do)
- [ ] Horizontal privilege escalation is blocked at every data access layer
- [ ] Admin endpoints are not accessible with standard user tokens
- [ ] Rate limiting is active on all sensitive endpoints

**Run:** SimpleBeacon `security-headers` + `database-patterns` scans

### Phantom Dependencies & Attack Surfaces

- [ ] All `package.json` dependencies are actively used in source code
- [ ] No deprecated or unverified third-party packages
- [ ] No `eval()`, `dangerouslySetInnerHTML`, or unsanitized dynamic code execution
- [ ] Lockfile (`package-lock.json` or `yarn.lock`) is present and up to date

**Run:** SimpleBeacon `npm-audit` + `dependency-vulns` + `unused-deps` scans

---

## 3. AI System Governance & Compliance

### Data Provenance & Licensing

- [ ] Training data sources are documented with proper attribution
- [ ] No unlicensed commercial data ingested into internal models
- [ ] Open-source licenses for all third-party components are catalogued

**Run:** SimpleBeacon `compliance` + `governance` scans

### Algorithmic Bias & Fairness

- [ ] Model decisions are tested across demographic segments
- [ ] Disparate impact metrics are measured and documented
- [ ] Human-in-the-loop review is mandated for high-risk automated decisions

**Run:** SimpleBeacon `eu-ai-act` scan (Annex III bias detection rules)

### Explainability (XAI)

- [ ] Model decisions can be traced to specific input features
- [ ] Audit logs exist for every inference with trace identifiers
- [ ] Documentation exists for non-technical stakeholders (regulators, customers)

**Run:** SimpleBeacon `eu-ai-act` + `documentation` scans
