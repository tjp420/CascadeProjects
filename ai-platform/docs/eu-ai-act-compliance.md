# EU AI Act compliance posture

This document describes how the Simplebeacon platform addresses **Regulation (EU) 2024/1689** (EU AI Act) readiness signals. It is engineering documentation, not legal advice or a conformity declaration.

## System classification

| Area                   | Posture                                                                                                            |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------ |
| Core Simplebeacon gate | Deterministic software quality and hygiene scanner — not an autonomous decision system                             |
| Optional LLM summaries | General-purpose generative AI add-on; users must disclose AI interaction per Article 50 in their own products      |
| DLP AI proxy           | Security control inspecting outbound AI API payloads — not a high-risk Annex III use case in default configuration |
| High-risk patterns     | Gate rules flag Annex III-style employment, credit, biometric, and similar patterns for manual review              |

## Article 50 transparency

User-facing surfaces that invoke optional LLM providers must include disclosure that content is **AI-generated** or that the user is **interacting with AI**. The internal dashboard Analyze view states that AI narrative is best-effort; client applications and operator deliverables must add product-appropriate copy.

## Technical documentation

- Risk assessment artifacts: `.simplebeacon/eu-ai-act-assessment.json` (generated by assess workflow)
- Inference accountability: `server/lib/ai-inference-audit-logger.js` — automatic inference logging with trace identifiers

## Operator deployment

- Set `OPERATOR_DASHBOARD_BASE_URL` or `PUBLIC_APP_URL` for deliverable links (avoid hardcoded localhost in production).
- Set `NODE_ENV=production` and `REQUIRE_AUTH=true` on production hosts.
- Configure provider API keys via environment or encrypted user settings — never commit secrets.
