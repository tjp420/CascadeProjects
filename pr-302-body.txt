feat(oram): add ORAM–Mixnet interop + bucket lock manager (batch=16)

Adds ORAM–Mixnet interop scaffold, fine-grained `lock_manager` to serialize bucket read/modify/write, deterministic DRBG padding, and microsecond telemetry.

Key changes:
- `executeCoordinatedFetch(quantizedQueue, opts)` now accepts:
  - `opts.oram`: a `PathORAM` instance used to perform real reads (`oram.access('read', id)`).
  - `opts.parallelLimit` (optional, number): concurrency throttle. Default: no throttling (fully parallel Promise.all behavior). When set to a finite positive integer the interop will schedule at most `parallelLimit` concurrent read tasks to limit CPU/IO pressure.
- `processMixnetBatch(packetBatch, opts)` passes `opts` through (e.g., `{ oram, parallelLimit: 4, batchSize: 16 }`).

Usage example:

```js
const res = await interop.processMixnetBatch(packets, { oram, parallelLimit: 4, batchSize: 16 });
```

Behavior notes:
- Result array preserves the quantized queue order.
- Dummy entries (`dummy-...`) return `{ id, data: null }`.
- `parallelLimit = Infinity` (default) -> fully parallel via `Promise.all`.
- Choose `parallelLimit` to match hardware (e.g., number of worker threads or expected IO concurrency). A conservative starting point is `Math.max(1, require('os').cpus().length)`.

Telemetry:
- `lock_manager` exposes `getMetrics()` and `resetMetrics()` with microsecond wait statistics, contention and timeout counters.

Tests:
- Added smoke runners: `ai-platform/tests/integration/run_lock_smoke.cjs` and `ai-platform/tests/integration/run_oram_smoke.cjs` that print metrics and verify batched fetch correctness.
