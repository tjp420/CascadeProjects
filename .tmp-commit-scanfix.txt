fix: scan worker posts progress for all file types, not just text-analyzed

The local scan appeared stuck on projects with many binary files (e.g., 7,754
files in a Games project) because scanFiles() in scan-worker.js had five code
paths that increment `processed`, but only the text analysis path posted
progress messages. For binary-heavy projects, 90%+ of files hit the binary/
skipped paths which processed files quickly but sent zero progress updates.
The UI showed "Worker started" then nothing for minutes until a batch-complete
message arrived.

scan-worker.js:
- Extract postProgress(currentFile) helper that posts { type: 'progress', ... }
  every 25 files
- Call postProgress from ALL six code paths: shouldSkipFile, invalid fileObj,
  isBinary, vendor skip, chunk timeout, text analysis, error catch
- Add batch-started message before each batch's scanFiles call
- Move const total to top of scanFiles (was redeclared inside loop)

localScanService.js:
- Remove dead duplicate worker.onmessage assignment (first was overwritten by
  second, making it dead code)
- Add batch-started handler that logs batch number and calls onProgress
- Add 30-minute overall scan timeout (SCAN_OVERALL_TIMEOUT_MS) with
  descriptive error message pointing to CLI for unlimited coverage
