feat(security): add software-simulated HSM vault provider for key derivation

Implement hsm-vault.cjs as a software-simulated Hardware Security Module
that provides isolated key derivation. The module is activated when
process.env.HSM_PROVIDER is set, with fail-open fallback to local HMAC
key derivation in crypto-utils.cjs if the HSM is unavailable or throws.

hsm-vault.cjs (new module):
- deriveKey(orgId, context): Generic HMAC-SHA256 key derivation using
  an internal simulated HSM root key. Returns 32-byte Buffer.
- deriveOrgKeyViaHsm(orgId): Hook-compatible function matching the
  existing call in crypto-utils.cjs deriveOrgKey(). Uses 'org-key'
  as the context.
- HSM root key is module-scoped and never exported (cryptographic
  boundary isolation)
- HSM_MOCK_ROOT_KEY env var enables deterministic testing by seeding
  the root key with a known hex value
- Throws TypeError for invalid orgId (caught by crypto-utils fail-open)

Integration with crypto-utils.cjs:
- deriveOrgKey() checks HSM_PROVIDER env var, routes through HSM if set
- If HSM module fails to load or throws, falls back to local HMAC
- HSM-derived keys differ from local fallback keys (different root seed)
- HSM-derived keys work for AES-256-GCM encrypt/decrypt round-trip
