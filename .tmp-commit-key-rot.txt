feat(security): add zero-downtime master key rotation store with grace window

Implement key-rotation-store.cjs that manages a dual-key validation
window during master key rotations. The active key is used for all
new encryption, while the previous key remains available for
decryption fallback during a configurable grace window (48h default).

This module implements the missing dependency that crypto-utils.cjs
already references via require('./key-rotation-store.cjs'). The
existing decrypt() function already has multi-key fallback logic
(line 112-116) — this store populates that fallback set.

key-rotation-store.cjs (new module):
- initKeyRing(currentKey): Initialize key ring with current ENCRYPTION_KEY
- getActiveKeyBuffer(): Returns 32-byte active key Buffer (matches
  existing crypto-utils.cjs interface at line 67)
- getDecryptionKeys(): Returns [{ keyHex }] array including previous
  key during grace window (matches existing interface at line 50-51)
- rotateKey(newKeyRaw, graceMs): Transitions active→previous, sets
  new active key via SHA-256 hash, starts grace window. Accepts
  string or Buffer input. Throws TypeError for invalid keys.
- purgeExpiredKeys(): Removes previous key after grace window expires
- getRotationStatus(): Returns metadata with truncated fingerprints
  (16-char hex), never raw key material
- reKeyValue(encrypted, decryptFn, encryptFn): Re-encrypts a single
  value from old key to active key
- reKeyStore(store, decryptFn, encryptFn, extractor, setter): Batch
  re-keying with callback-based value extraction/setting
- persistState(): Best-effort persistence to KEY_ROTATION_STORE_PATH
  (saves only fingerprints, never raw keys)
- _reset(activeKey): Test helper to reset key ring state

Configuration:
- KEY_ROTATION_GRACE_MS — grace window in ms (default: 172800000 = 48h)
- KEY_ROTATION_STORE_PATH — optional path to persist rotation state
